# Requirement Gap Analysis Report

## Executive Summary
This report analyzes the existing implementation of the **Loan Intelligence Platform** against the comprehensive master specifications and highlights specific gaps, architectural refinements, and remediation plans across ten critical dimensions.

---

## Gap Analysis Matrix

| # | Requirement Dimension | Existing Implementation / Documentation | Missing or Inconsistent Part | Proposed Correction | Verification Method |
|:---|:---|:---|:---|:---|:---|
| **1** | **CreditProfile Entity** | `credit_score` is stored directly on `Applicant` using Gaussian sampling. No standalone `CreditProfile` entity exists. | Missing `CreditProfile` table (`credit_profile_id`, `applicant_id`, `synthetic_credit_score`, `score_band`, `payment_history`, `credit_utilization`, `active_facility_count`, `assessment_date`, `score_version`, `source_type`). Credit score is not derived formulaically from payment history & debt burden. | Implement `CreditProfile` entity (Applicant 1:N CreditProfile) with deterministic scoring formula derived from payment history, active facilities, and revolving utilization. Preserve historical profiles. | SQLAlchemy model tests, schema migration check, and formulaic score assertion tests. |
| **2** | **Anomaly Staging Architecture** | Anomaly injector modified operational records in-place (e.g. duplicate disbursement collided with the DB unique constraint). | Operational database constraints were in tension with deliberate malformed anomaly records. | Implement a separate **Anomaly Staging Layer** (`data/anomalies/` and `AnomalyStaging` records). Baseline operational DB preserves strict constraints; detector inspects both baseline and staging records with zero ground-truth leakage. | Anomaly detection tests, DB constraint validation, and ground-truth evaluation report. |
| **3** | **Decision-Rule Precedence & Overrides** | 10 rules executed sequentially. Simple override mechanism. | Missing formal conflict resolution specification, tiered severity hierarchy (`HARD_FAIL`, `SOFT_FAIL`, `INFO`, `PASS`), and dedicated Underwriter Human Override workflow with audit logging. | Create formal precedence engine, reason code aggregation, and `DecisionOverrideHistory` ledger recording human underwriter ID, rationale, previous status, and timestamp. | Unit tests for multi-rule collision, hard vs. soft fail precedence, and underwriter override execution. |
| **4** | **Financial Calculation Rigor** | Computes standard DTI, FOIR, Reducing EMI, Disposable Income. | Terminology needs distinction between **Existing DTI** (existing debt / gross) vs. **Total DTI** (existing debt + proposed EMI / gross), plus explicit zero-income, missing-income, and fractional-cent rounding guards. | Formalize Existing DTI, Total DTI, FOIR, Disposable Income, reducing-balance amortization formulas with zero/missing income guards and document in `docs/calculation_methodology.md`. | Pure math unit tests covering boundary zero/negative values and precision reconciliation. |
| **5** | **Source Manifest & Data Provenance** | Synthetic generator metadata recorded in `DatasetGenerationRun`. | Missing explicit `data/source_manifest.json` recording synthetic provenance, seed (`20261022`), generator version, license, attribution, transformations, and discarded fields. | Generate `data/source_manifest.json` conforming to open data standards and document synthetic provenance. | JSON schema validation and integrity hash checking. |
| **6** | **Independent Lifecycle State Machines** | Application status followed general state transitions; disbursement was conditionally created. | State machines across Application, Decision, Document, Disbursement, and Repayment need explicit independent definition and enforcement. | Implement 5 formal state machines with transition matrices preventing unauthorized auto-disbursements and decoupling approval from payout eligibility. | Lifecycle transition unit tests preventing illegal transitions. |
| **7** | **Expanded Evaluation Metrics** | Metrics covered Anomaly Precision, Recall, and F1. | Missing holistic metrics: decision consistency rate, calculation error rate, repayment reconciliation rate, referential integrity rate, turnaround time, and prohibited feature leakage checks. | Implement `backend/app/evaluation/comprehensive_metrics.py` computing all required operational and model quality metrics from actual database records. | Comprehensive metrics report output verification (`reports/comprehensive_evaluation.json`). |
| **8** | **Security & Expanded API Specifications** | Unauthenticated REST API with standard endpoints. | Missing RBAC (Customer, Operations Analyst, Risk Reviewer, Admin), secure password hashing, JWT bearer auth, and endpoints for overrides, generation, and validation. | Add auth router (`/api/v1/auth`), role-based dependencies, PBKDF2/sha256 password hashing, audit logging, and customer data boundary enforcement. | API integration tests for unauthorized access, role enforcement, and token lifecycle. |
| **9** | **Documentation Harmonization** | Initial documentation created. | Docs need updates reflecting `CreditProfile`, Anomaly Staging, 5 State Machines, Expanded Metrics, and Source Manifest. | Update all 12 core documentation files and implementation checklists. | Markdown link validation and consistency verification. |
| **10** | **Continuous Working Verification** | Working starter generation and test suite. | Codebase must remain fully functional and all existing tests plus new tests must pass without regressions. | Execute full Pytest suite, regeneration, and frontend build verification. | 100% test pass rate across all suites. |
